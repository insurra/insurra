# Insurra shared foundation — Phase 1.5 + account authentication

- Scope is shared contracts, storage primitives, additive migrations, actor/session/consent boundaries, versioned KB shapes, generated types, documentation, tests, and the implemented Google OAuth account boundary. Keep existing demo behavior. Product workflows beyond the landing/login/callback surfaces, AI/extraction, claims/triage engines, external actions and deployments remain deferred.
- Team feature ownership and branch assignments are explicitly deferred until maintainer approval after foundation handoff. Do not assign people, add CODEOWNERS, allocate branches, or create TEAM_HANDOFF.md.
- Read local PRDs in this order when available: Summary, Daftar Screen, Kontrak API, Requirement (including multiline acceptance criteria), Skema Data; then docs/prd/DECISIONS.md and mappings. These CSVs are local-only, immutable references; never stage them. README and agent guidance must be understandable without them. Missing required PRDs must be reported, not fabricated.
- Python Pydantic v2 is the domain source of truth: FastAPI → backend/openapi.json → openapi-typescript → frontend/src/lib/api/types.gen.ts. Never hand-edit generated artifacts or create parallel domain schemas. Use `make generate-types` and `make check-contracts`.
- Use `/api/v1` for new API contracts. Preserve working legacy foundation routes/response shapes. Clearly distinguish live, 501 contract-only and planned routes in documentation; future success schemas do not imply working features. Do not scaffold nineteen screens.
- Use stable English snake_case JSON and explicit enums; UI copy is Indonesian. Forbid extra input fields, validate UUID/date/query boundaries, and keep ApiError(code,message,details,request_id) consistent. Never echo raw passwords, tokens, questions or document values in error details/logs.
- Actors resolve through either a validated opaque `X-Demo-Session` token or an opaque authenticated-account bearer session. Demo and account sessions remain distinct; never accept a caller-supplied account ID as authentication. Every owned path/body ID must be scoped before a 501 response; missing and foreign objects both return 404.
- Three separate purpose grants default false: process_documents, external_ai, retention. Recheck current database grants for each protected call; AI-capable routes require documents AND external AI. Legacy /consent controls documents only. Never infer AI/retention permission from historical booleans or from visiting a screen. Privacy management does not require a processing grant.
- Approval must be actor-owned, persisted and bound to the exact canonical server payload hash before any future execution. All executors and real/sandbox submissions currently return 501; never claim false deletion, processing, approval or execution success.
- Use SQLAlchemy 2 and additive Alembic revisions. Do not rewrite released migrations, run create_all at startup, reset SQLite, drop existing user data or silently upgrade statuses. Keep UUID/JSON/constraints portable to SQLite/PostgreSQL. 0002 requires online migration for its historical consent backfill.
- Country categories, document templates, vocabulary, rules, tasks, verification steps and emergency/red-flag metadata live under versioned kb/{ISO_CODE}. Envelopes use schema_version 1.5 plus version/source_url/checked_at/verification_status. Unknown facts stay empty/null and UNVERIFIED. No country branches or invented medical/regulatory/insurance facts.
- Preserve original evidence, currency and values. Missing/unknown never means excluded. No fabricated clauses/pages/citations, benefits, prices, diagnoses, legal certainty or external actions. Python computes inclusive calendar intervals and decimal money deterministically; never use LLM arithmetic.
- Local setup: copy .env.example to .env, `make setup`, `make migrate`, `make seed`; run `make dev-backend` and `make dev-frontend` separately. Demo mode needs no paid credentials; Google login requires server-side OAuth credentials and an exact authorized callback URI. Keep credentials server-side; never place privileged values in `NEXT_PUBLIC_*`.
- Before relevant commits: `make test`, `make test-client`, `make check-contracts`, `make check`; run frontend desktop/mobile `npm run test:e2e` when session/client/demo behavior changes. Add targeted migration-upgrade, scope, purpose-revocation and error-contract regression tests. Avoid unrelated dependency upgrades.
- Python: Ruff format/check, Python 3.11+, 100 columns. TypeScript: strict mode, typed native fetch, no duplicate domain types. Respect frontend framework-generated rules and preserve that block byte-for-byte.
- Use logical Conventional Commits; review staged diffs/secret patterns. Preserve pre-existing user edits and Git history. Never auto-push, amend, reset, rebase, rename branches, change remotes or deploy.

- The original `docs/prd/*.csv` files are intentionally ignored. Check the tracked `docs/prd/API_CONTRACT_MANIFEST.json` with `make check-prd-contracts`; when local CSVs exist, run `make check-prd-source` to catch PRD/source drift. Route coverage alone is not payload-shape conformance; document deviations before freezing contracts.

- Canonical PUT `/api/v1/profile` returns `{profile,suggested_docs}`; GET remains bare UserProfile. Same-country partial updates preserve omitted fields; country switches follow the context-reset rules below. Validate the resulting state before persistence. Suggestions require VERIFIED versioned country KB data; unverified placeholders return []. Claim list items carry case/checklist; draft-form uses literal `pending`; approval/rejection success contracts are status-only. Claim/action product routes remain 501. Run payload regressions as well as route/transport checks before changing contracts.

- Country edits select new KB context without rewriting original insurance/document countries. Clear omitted country-bound residence/visa/budget fields on a country change; preserve explicitly supplied values and same-country merge behavior. Country mismatch is NEEDS_VERIFICATION with no computed gap, even when no visa rule matches. See docs/prd/COUNTRY_INTEGRATION.md for scope, mixed-country limitations and inactive KB prerequisites; use SCREEN_ROUTES.md for exact demo→PRD frontend routes without creating aliases/screens.
