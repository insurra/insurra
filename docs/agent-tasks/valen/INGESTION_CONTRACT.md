# Coverage, benefit and evidence integration

Valen reads existing `AccountCoverageRow`/`AccountFieldRow`/`AccountDocumentPageRow`; it does not run a second extraction pipeline or copy normalized benefits into another table. Account coverage `kind` is mapped through KB `coverage_types[].aliases`, or an explicitly reviewed `coverage_type` field. An ambiguous policy booklet remains unclassified.

Fields must carry the same authenticated account and coverage, with a source document owned by that account. FOUND requires a value and either user confirmation or confidence >= 0.8 plus a source page. Unverified source dates never become verified through a profile edit. Manual profile fields without a coverage association are not borrowed by arbitrary policies.

Reviewed benefit keys: `benefit_<category>_limit_amount`, `_used_amount`, `_currency`, `_period_start`, `_period_end`, `_excess`, `_network_only`, `_requires_referral`, `_claim_mode`, `_coverage_rate`, `_coverage_status`, `_exclusion_quote`. Monetary values are nonnegative decimal strings; currency stays the source ISO code. The period must contain the evaluation date before calculating a remaining amount; missing usage/period/currency means unknown. Used > limit is clamped to zero with an explicit over-limit warning. No currency conversion or inferred benefits.

Clause indexing is idempotent. `clause_chunks` stores owner/coverage/document/page, character offsets and SHA-256 of the slice. Exact text remains in the original retained account page only. Composite foreign keys reject a cross-account coverage or document; page references cascade on deletion. Re-read/hash-check the page on retrieval and citation validation. No vectors or raw questions in logs.

Retention is optional for document processing. Account ingestion now keeps original bytes and raw pages only when retention is explicitly granted. Reviewed structured fields remain available without it. Retention revocation removes raw pages, offsets and chat history transactionally through the existing privacy endpoint; regrant never restores deleted content. Processing/AI revocation clears derived retrieval/history and denies subsequent calls. A future approved temporary-page adapter can support Q&A without retention; the current account API supplies no such material, so Q&A must explain that evidence is unavailable and request a fresh upload under the desired consent. Delete the old document before re-uploading identical bytes, following existing duplicate-upload protection.

`0008` extends the existing `claim_cases` table for account or demo ownership, preserving old cases/actions. New bounded interaction tables contain dismissals, rolling question timestamps, last ten retained chat turns, and content-free short-lived pathway decisions. No second profile, account, coverage, or claim-case model is introduced.


Pathway estimates additionally require reviewed category coverage_status=COVERED, coverage_rate as a decimal string from 0 through 1, excess, network_only/requires_referral booleans and claim_mode (DIRECT_BILLING or REIMBURSEMENT). Provider/network and referral context comes from provider_network_status (in_network/out_of_network) and referral_status (available/not_required); network-only benefits cannot use an out-of-network estimate, and a required referral must be available. ID kapj_status stays unknown unless explicitly confirmed or not_applicable. Missing, contradictory or unverified prerequisites keep costs null. A reviewed same-currency KB tariff is also required; no actual tariff is shipped.

Application state is registered in app/models/workspace_state.py. Existing claim and account models remain their original definitions; file/module renaming introduced no new table or migration. See VERIFICATION.md for model-registration and migration checks.
