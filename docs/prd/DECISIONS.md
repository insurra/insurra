# Foundation alignment decisions

Baseline: seven foundation commits through `56a3422`. Read all five local CSVs with a CSV parser, including multiline descriptions/acceptance criteria. They contain 55 stories (44 P0, 11 P1; the Bonus screen has no standalone story row) and 19 screens. This pass stabilizes shared foundations; story acceptance criteria do not authorize feature implementation or ownership assignments.

| Difference / contradiction | Alignment decision |
| --- | --- |
| PRD uses `/api/...`; foundation uses `/api/v1/...` | All new routes use `/api/v1`. Record the one-to-one mapping in API_CONTRACTS. Keep existing utility/legacy foundation routes and response shapes. Do not add an unversioned API layer. |
| PRD tool outputs say Zod; stack uses Python/Pydantic | Pydantic v2 is the server source of truth. Generate OpenAPI then TypeScript with openapi-typescript. No parallel handwritten Zod domain schema. |
| PRD accounts, verification, seven-day inactivity expiry vs 24-hour demo sessions | Production auth remains 501. Define distinct demo/account actor interfaces, but resolve only validated demo tokens. Never treat an account UUID, body owner ID or arbitrary Authorization header as identity. Demo expiry remains unchanged. |
| One legacy consent vs three purposes | Add `purpose_consents` alongside retained `consents`. Three purposes default false. Migrate legacy boolean only into `process_documents`; external_ai and retention stay false, with no invented grant timestamps. Preserve original rows and audits. `/consent` remains a document-processing compatibility view; its PUT never grants other purposes. Canonical GET/POST `/consents` manages one explicit purpose with policy version/timestamps. |
| Legacy consent screen says documents and AI together | Minimal copy correction only: the existing control grants document processing. External AI requires a separate canonical consent. No three-card redesign or new privacy screen in this pass. |
| Processing vs reading/managing data | Seeded profile/record, audit and deterministic visa calculation remain available without processing consent. AI-capable upload/extraction/Q&A/evidence require process_documents AND external_ai. Local document/field/claim processing requires process_documents. Privacy deletion requires identity/confirmation, not processing permission. Retention is optional, never a processing prerequisite. |
| Retention revocation implies original-file cleanup in PRD | No uploaded originals are stored in Phase 1.5. Record/revoke consent and timestamps, but do not claim deletion of files. Real storage must add atomic cleanup and guard rechecks before activation; privacy deletion stays 501. |
| PRD profile PUT returns `{profile,suggested_docs}`; existing callers expect bare profile | Preserve bare UserProfile and required legacy fields. Add optional validated PRD profile metadata; suggested-doc computation remains deferred. Map visa_end_date to existing visa_expiry_date; employment_status is additional metadata, occupation remains compatible. |
| Lowercase PRD enums vs existing uppercase values | Preserve existing uppercase domain enums, lowercase purpose values exactly as PRD. Explicitly map `done` → COMPLETED and `found` → FOUND; never rewrite stored statuses. Canonical claim lifecycle is distinct from legacy draft/checklist readiness. |
| Summary says reuse duplicate uploads; US-03-01 rejects them; evidence story reuses results | Future ordinary duplicate uploads return 409 within the same actor scope. Processing retry/evidence reuse may reuse actor-owned extraction by hash. No cross-actor cache disclosure or cache implementation now. |
| Unknown/missing vs excluded/not owned | Preserve UNKNOWN and NEEDS_CHECK. A missing field is not evidence of exclusion. Even if a coverage-needs acceptance example labels missing dental data “Belum punya”, the safer contract leaves ownership unconfirmed without evidence. |
| PRD cites concrete laws, emergency numbers and demo policy quotes without verified local sources | Do not adopt those as verified facts. KB placeholders remain UNVERIFIED with null checked_at/source_url; medical routing, source-backed requirements and quotes stay disabled until reviewed. |
| Two PRD examples use different dates for the 76-day gap | Preserve existing synthetic Raka dates (coverage through 2027-04-15, visa through 2027-06-30) and the inclusive potential interval of 76 days. No automatic visa-breach finding. |
| Future object routes could return 501 without checking IDs | Resolve session first, then consent if required, then actor-owned object existence. Missing and foreign IDs both return 404; owned deferred features return 501. Payload IDs (coverage, document references) also need ownership checks. No success mutations. |
| PRD data tab lists deep feature tables and vector embeddings | Add only consent records and minimal owner-scoped document/extraction/claim/action primitives needed to validate identifiers/provenance. Keep insurance JSON and existing tables intact. Defer OCR pages, benefits normalization, clause vectors, status histories, feature algorithms, P1/bonus storage. |
| GET audit originally returns an unbounded array | Preserve array shape and exact event_type filter. Add bounded optional limit/offset, total-count header and PRD `type` category alias. Avoid a breaking pagination envelope. New claim list uses a typed pagination envelope. |
| PRD chat streams and can redirect to emergency | Specify JSON response/redirect and SSE response/event schemas; HTTP remains 501 after guards. Client can expose native byte streams; no chat generation or streaming engine is implemented. |
| Sandbox claim submission appears in a story but not the API CSV | Document a proposed versioned stub from US-10-04, requiring actor, processing consent, owned action and server approval/hash checks; do not implement an insurer simulator or execute actions. |
| Signup/reset/verify routes absent from API CSV but required by stories | Record proposed canonical route names separately as story-derived specifications; register honest auth stubs only. No provider, password persistence or account authentication is implemented. |
| P1/Bonus screen stories conflict with narrow phase scope | Trace all names/IDs faithfully; leave features, tables and screens deferred. No team handoff, CODEOWNERS, feature branches or assignments. |
| Local PRD directory is already ignored by an uncommitted user change | Preserve that user change. Add the explicit CSV ignore rule as our own staged change; force-stage only named generated Markdown mapping files. Never stage CSVs. Preserve CSV hashes byte-for-byte. |

Detailed route/status mappings and storage justifications are maintained in adjacent documents. README and all AGENTS files must remain self-contained without the local CSVs.

Migration revisions: 0001 is untouched; 0002 adds consent/scoped identities and backfills online; 0003 adds approval payload JSON without changing approval statuses. Online execution is required for 0002; table DDL portability is checked separately. Resource schema 1.5 uses country resource version 0.2.0 envelopes; direct file consumers must unwrap data while the shared loader preserves existing views.
