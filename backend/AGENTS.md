# Insurra backend conventions — Phase 1.5

- Shared technical foundations only: schemas, API stubs, storage primitives, consent/scopes, KB structures, tests. No feature pipelines, account auth integration, OCR/AI/retrieval, medical triage, claim execution, insurer simulator or ownership/branch assignments.
- Consult root AGENTS.md, README, and docs/prd mappings/DECISIONS. Local CSVs are immutable and excluded from Git. Keep docs self-contained.
- Pydantic v2 extra=forbid defines stable snake_case contracts/enums. `/api/v1` is canonical. Keep existing live endpoints/shapes; sensitive future routes check session, purpose and owned IDs before returning ApiError/501. No fake 2xx results.
- Actor interfaces distinguish DEMO_SESSION from AUTHENTICATED_ACCOUNT. Only hashed opaque demo tokens resolve today. Never trust caller owner/account IDs; path and payload references must resolve through scoped repositories. Foreign/missing objects return the same 404.
- process_documents, external_ai and retention are independent current database grants. AI-capable processing requires the first two; optional retention is not implied. Legacy boolean APIs manage documents only. Revocation must block later protected calls; privacy management remains available without processing permission.
- Use additive SQLAlchemy 2/Alembic schemas, composite owner foreign keys and portable UUID/JSON types. Preserve initial migrations, sessions, insurance JSON, historical booleans and audit entries. Never create_all/reset at startup. 0002 backfills consent online without inferring AI/retention grants.
- Documents/fields/claim/action tables are identity/provenance/approval primitives, not working product workflows. Do not silently normalize insurance records, promote statuses, or create speculative P1/bonus tables. Future approval/execution must verify persisted ownership and exact canonical payload hash.
- KB resource schema 1.5, per-country version consistency, source/verification metadata and reference checks are required. New countries are folders, not country-specific conditionals. Unknown regulatory/medical contents stay empty/null and UNVERIFIED; no triage/recommendation algorithm is activated.
- Deterministic Python dates (inclusive endpoints) and decimal-string money only. Preserve source evidence and original currency; absent evidence never means not covered. No fabricated quotations/pages, legal findings or external effects.
- No raw tokens/passwords/questions/document text in logs or error details. Audit metadata is an operational allow-list. No secrets in source, tests or browser configuration; tests use synthetic credentials and mock any provider integration.
- From repository root: `make migrate`, `make seed`, `make test`, `make generate-types`, `make check-contracts`, `make check`. Python 3.11+, Ruff check/format. Test fresh and populated upgrades, idempotent seeding, consent/revocation, IDOR, error/OpenAPI contracts and unchanged Raka 76-day/ID non-applicability results before relevant commits.
- Use Conventional Commits, stage only intended files, inspect staged diffs for secrets, preserve unrelated edits, and never auto-push or rewrite Git history.

- The original `docs/prd/*.csv` files are intentionally ignored. Check the tracked `docs/prd/API_CONTRACT_MANIFEST.json` with `make check-prd-contracts`; when local CSVs exist, run `make check-prd-source` to catch PRD/source drift. Route coverage alone is not payload-shape conformance; document deviations before freezing contracts.

- Canonical PUT `/api/v1/profile` returns `{profile,suggested_docs}`; GET remains bare UserProfile. Same-country partial updates preserve omitted fields; country switches follow the context-reset rules below. Validate the resulting state before persistence. Suggestions require VERIFIED versioned country KB data; unverified placeholders return []. Claim list items carry case/checklist; draft-form uses literal `pending`; approval/rejection success contracts are status-only. Claim/action product routes remain 501. Run payload regressions as well as route/transport checks before changing contracts.

- Keep active profile country separate from original record/DocumentRow country. Country switches clear omitted city/timezone/institution/visa dates/budget/currency, without changing insurance, consents or provenance. A mismatched country assessment is NEEDS_VERIFICATION with null gap and no borrowed rule source, including KBs with no matching rule. Same-country partial merge and explicit destination fields remain supported. Country rules/empty-resource boundaries are in docs/prd/COUNTRY_INTEGRATION.md.
